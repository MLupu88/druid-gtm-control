1. Dashboard

Title: “What needs my attention today?”

Show:
- sending state using ENGINE_MODE_LABELS
- active scoring view using QUEUE_SOURCE_LABELS
- live data status
- automation status
- counts by recommendation type using OUTPUT_TYPE_LABELS
- counts by status using STATUS_LABELS_V3 when available
- “Needs Your Attention” list using real queue rows only
- “Recent Activity” using real rows/action data only if available

If the queue is empty, show a calm empty state. Do not invent activity.

2. Review Queue

Main work list.
One row per account or signal from /api/sheets/queue.

The recommendation must be the first and most visually important item.
The numeric score is secondary.

Use:
- OUTPUT_TYPE_LABELS for recommendation/output type
- IDENTITY_LABELS for identity confidence when available
- BLOCK_REASON_LABELS for blocked reasons
- costLabel(row) for cost/credit copy
- visitorSafeCopy(row.why_now, row.visitor_claim_allowed) before rendering activity or reason text

Support:
- search by company/domain/contact
- filter by recommendation type
- filter by needs review
- empty state if no rows

Do not show raw field names.
Do not show raw internal enum values when a label exists.

3. Account Detail

Open from Dashboard or Review Queue.

Sections:
- About this account
- Why this recommendation
- What led here
- Score explanation
- People/contact
- What this would cost
- Take action
- What happened on the call, only if call data exists

Use plain-language labels from the shared contract.
Run activity/reason text through visitorSafeCopy.
Do not claim a specific person did something unless visitor_claim_allowed allows it.
If data is missing, show a calm “Not available yet” state, not broken UI.

5. Try a Sample Lead

Build the view but keep it safe.

Use the title:
“Try a Sample Lead”

Use this explanation:
“Send a made-up example lead through the system to see how it gets scored and what shows up in the queue. This safely writes a real test row — it does not contact anyone.”

Presets:
- A person from a US company visits our site
- A company in Europe visits our site
- A company in Europe visits and we find a likely contact
- Someone browses anonymously
- A known contact from our CRM engages
- One of our own team members
- A visitor with a personal email address

Important:
- It must post only to the server-side route that maps to ENDPOINTS.testSignal.
- Never post test signals to live intake.
- If the backend proxy route is missing, show the page but disable the submit button and say the connection is not enabled yet.
- Do not contact anyone.

Backend write/proxy routes:

If missing, create server-side routes only:

POST /api/n8n/activate
POST /api/n8n/decision
POST /api/n8n/action
POST /api/n8n/config
POST /api/n8n/test-signal

These must:
- run server-side only
- use N8N_BASE_URL and N8N_WEBHOOK_SECRET from process.env
- never expose N8N_WEBHOOK_SECRET to the browser
- use endpoint paths from ENDPOINTS in @workspace/gtm-shared
- include the full row snapshot when acting on a row
- include approved_by, approved_at, reason
- require a reason for all human actions
- return the n8n result honestly

Do not call Retell, HubSpot, Gmail, Cognism, Salesforge, Dripify, Slack, LinkedIn, Google Ads, Meta Ads, or any vendor API directly from the app.
