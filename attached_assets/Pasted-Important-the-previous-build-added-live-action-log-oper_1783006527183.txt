Goal:
Add a clear, safe “Sample Data” experience that lets the UI show realistic review rows even when the live Google Sheet queue is empty.

Rules:
- The app should still show that live data is connected.
- But when the live queue has 0 rows, allow the operator to switch to a sample-data view.
- The UI may say “Sample data” as a small honest badge.
- Do not use the word “mock” anywhere in rendered UI.
- Do not imply sample rows are real leads.
- Do not allow sample-row actions to call n8n.
- Sample-row actions should open the same confirmation modal, but the final confirm button should be disabled or should show “Preview only — no action will be sent.”
- The goal is to demonstrate the workflow, not execute it.

Build these features:

1. Sample data toggle

Add a small control near the top of Dashboard and Review Queue:

Live data / Sample data

Behavior:
- Live data remains the default.
- If live queue has 0 rows, show a helpful empty state with a button:
  “View sample workflow”
- When sample data is selected, use rows from @workspace/gtm-shared/mockData.js.
- Show a small badge: “Sample data”
- Make it obvious but not alarming.

2. Dashboard with sample data

When sample data is selected:
- Show counts by recommendation type.
- Show “Needs Your Attention” using sample rows.
- Show a realistic Recent Activity section, but label it as sample data.
- Do not invent integrations.
- Do not say email/LinkedIn/CRM/ad actions were sent.
- Use STATUS_LABELS_V3 when relevant.

When live data is selected and empty:
- Keep the calm empty state.

3. Review Queue with sample data

When sample data is selected:
- Render sample rows as if they are real queue rows.
- Recommendation/output type must be first and visually strongest.
- Score is secondary.
- Use:
  - OUTPUT_TYPE_LABELS
  - IDENTITY_LABELS
  - BLOCK_REASON_LABELS
  - costLabel()
  - visitorSafeCopy()

Support:
- search
- filtering by recommendation type
- filtering by needs attention

4. Account Detail with sample data

Opening a sample row should show the full Account Detail experience:
- About this account
- Why this recommendation
- What led here
- Score explanation
- People/contact
- What this would cost
- Take action
- What happened on the call only if call data exists

Use sample data to make the page feel complete.
If a field is missing, show calm fallback text.

5. Action modal in sample mode

For sample rows:
- Show the same action buttons that would appear in the final app.
- Buttons must come from BUTTONS / buttonsForOutput / buttonDisabled / buttonDisabledPhaseC.
- Every action opens the confirmation modal.
- Modal must show:
  - what would happen
  - whether it would send or only log
  - cost line from costLabel()
  - reason field

But:
- Do not post to n8n for sample rows.
- Final confirm button should say:
  “Preview only”
  or be disabled with:
  “Sample data — no action will be sent.”
- This is for understanding the workflow only.

Keep Settings connected to live config.

Settings should still show:
- live data connected
- sending state
- active scoring view
- automation engine reachable
- queue writing state
- US calling permission
- do-not-contact list
