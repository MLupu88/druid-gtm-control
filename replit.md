# DRUID GTM Mission Control

An internal review cockpit for a GTM signal engine powered by n8n and Google Sheets.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API/backend server (port from env)
- `pnpm --filter @workspace/druid-gtm run dev` — run the React + Vite frontend
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React 19 + Vite + Tailwind CSS + shadcn/ui (artifacts/druid-gtm)
- Backend: Express 5 (artifacts/api-server)
- Shared: GTM contract + mock data (lib/gtm-shared)
- DB: PostgreSQL + Drizzle ORM (lib/db) — not yet used
- Validation: Zod (zod/v4), drizzle-zod
- API codegen: Orval (from OpenAPI spec)

## Architecture decisions

- All vendor secrets (Google SA key, n8n tokens) live only in server-side env vars — never sent to the browser.
- The browser talks exclusively to `/api/*` on the Express server; the server talks to Google Sheets and n8n.
- Shared contract types (lib/gtm-shared) are imported by both the server and the client build via the workspace.
- OpenAPI spec is the source of truth for all typed API contracts between frontend and backend.

## Product

Internal tool for reviewing, approving, and rejecting outbound GTM signals (email sequences, LinkedIn, ads) generated by an n8n automation engine, sourced from Google Sheets.

## Gotchas

- Do not call vendor APIs (Google, n8n) from the browser — route all of that through `/api/*` on the Express server.
- Do not add Slack, CRM, email sending UI, LinkedIn UI, or ad platform UI.
- The app reads Google Sheets server-side and sends approvals to n8n server-side.
